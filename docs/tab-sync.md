# 別タブ間の同期

同じローカルコアへ接続したタブは一つのプロジェクトを共有する。セル、表の追加、行列の追加、配置、ファイル読み込み、Undo / Redo の結果を自動で反映する。Undo / Redo は当面プロジェクト共通で、別タブから行った操作も戻る。

## 操作と競合

- セルやノードタイトルを編集中は、そのタブの画面へのスナップショット適用を保留する。別タブが表を置き換えたり Undo で行を消した場合も、入力欄を途中で消さない。セルからフォーカスが外れた時に反映する。
- タイトル確定・セル確定・範囲貼り付けには編集前の値を添える。Rust が現在値と比較し、対象範囲が変わっていれば操作全体を拒否する。
- 拒否した操作は「未反映の操作」に入力内容を残す。「現在の状態に再適用」または「この操作を破棄」を選ぶ。再適用も最新の比較条件を付ける。対象の表自体がなくなった場合は入力をコピーして回収できる。
- 未反映の操作がある間は保存を止める。未反映入力はファイルに含まれず、このタブのメモリだけに存在するため、ページを閉じる前に解消する。
- ドラッグ・サイズ変更は操作終了時に共有する。操作中の配置はローカルで保持する。失敗した配置も再適用・破棄できる。
- パン・ズーム、選択、スクロール位置はタブごとの表示状態で、同期しない。

同じセルの競合は値の比較による検出であり、「一度変更して同じ値に戻した」操作履歴までは検出しない。行列はまだ添字で識別している。行列の並べ替え・削除を実装する際は安定した ID に拡張する。

## 通信

`GET /api/project/events` の SSE で revision の変更を通知し、タブは `GET /api/project` を再取得する。接続時にも通知するため、初期取得との隙間や一時的な切断中の変更を回収する。通知は最新 revision へ集約し、取得中の通知も再取得する。遅れて返った古いスナップショットでは画面を巻き戻さない。

更新と通知は同じロック内で行う。操作 API は revision 不一致に HTTP 409 を返す。比較条件付きセル操作のみ、最新状態を取得して一度再試行する。それ以外の拒否・通信エラーは入力を保持し、無条件で自動再送しない。通信エラーではサーバーで操作済みの可能性もあるため、再適用前に現在の状態を確認する。

通信の再接続は EventSource に任せる。画面下部に「同期中」「再接続中」を表示する。コアプロセス自体の再起動では revision と Undo 履歴がリセットされるため、開いているタブを再読み込みする。プロセスをまたぐ世代識別・自動復旧は未実装。

保存済み表示はタブごとに管理する。別タブで保存しても、そのファイルが確保されたことをこのタブから保証できないため、保存済み扱いにはしない。

## 検証（2026-11-22）

- 自動テスト: 通知後の再取得、古い応答の拒否、編集中の画面更新保留、未反映入力の保持と再適用、保存停止、Rust のセル比較と共通 Undo。
- 独立したテスト環境の2タブ: セル編集の伝播、同じセルを編集中の入力保持と競合表示、再適用、相互の Undo / Redo、移動確定後の配置一致。
- 実際の日本語 IME 候補選択中の別タブ更新、通信切断・復旧のブラウザーでの実地検証は未実施。
