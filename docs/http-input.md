# HTTP入力

「入力を追加」→「HTTP」で追加する。URLとメソッドを指定し「リクエスト」で取得する。GET／HEAD／POST／PUT／PATCH／DELETE／OPTIONSに対応し、必要なら「送信ヘッダー・本文」を開いて指定する。送信ヘッダーは1行につき `名前: 値`。Host・Content-Length・Transfer-Encoding・Connectionはクライアントに任せる。

ノード内のプレビューは先頭20,000文字まで表示する。出力・保存には全文を保持する。

出力は「レスポンス」という1列で、改行ごとに行を分ける。結果テキスト・結果ツリー・フィルタなどへ接続できる。

| 出力 | 内容 |
| --- | --- |
| body（初期値） | レスポンス本文 |
| headers | レスポンスヘッダー（`名前: 値` の行） |
| raw | ステータス行＋ヘッダー＋空行＋本文 |

rawはHTTPクライアントが解析した情報を組み直したテキストで、通信の生バイト列ではない。ヘッダー名の大小文字・順番や元のステータス理由句の完全再現は保証しない。出力の行区切りはLFに正規化する。

## 更新と保存

- 取得はボタン操作時だけ。起動・復元・Undo／Redo・接続・無関係な編集でリクエストを再送しない。定期取得は未実装。
- raw／headers／bodyは取得済みレスポンスから切り替えるため再通信しない。出力変更は下流へ伝播し、下流の手動更新も尊重する。
- 取得が完了すると、リクエスト設定・最後に成功したレスポンス・出力選択を共通操作で確定し、自動保存・別タブ同期・Undoの対象にする。取得前の入力途中の設定は保存されない。
- 通信失敗・容量超過・文字コードエラーでは前回のキャッシュを残し、エラーと更新待ちを表示する。HTTPの4xx／5xxは通信自体の失敗ではなく、そのレスポンスを通常どおり出力する。
- 待機中はRustのプロジェクトロックを解放する。待機中にプロジェクトのrevisionが変わった場合（無関係な変更も含む）、または同じノードで新しいリクエストが始まった場合は古い応答を破棄する。自動再送はしない。
- 送信ヘッダー（認証情報を含む）、本文、レスポンスはプロジェクト内に平文で保存される。プロジェクトの共有時は内容を確認する。HTTP先に生じた変更はUndoでは戻らない。

## 現在の制限

- HTTP／HTTPSのUTF-8テキスト。バイナリや他の文字コードは非対応。
- URL8192バイト、送信ヘッダー16384バイト、送信本文100000バイトまで。
- レスポンスはヘッダー＋本文で10 MiB（10,485,760バイト）以内。選択した出力は5000行以内・1行11 MiB以内（rawのステータス行などの追加分を含む）。長いJSON行も結果ツリーなどへ渡して保存・復元できる。プロジェクト全体の保存上限は128 MiB。
- 全体30秒、接続10秒のタイムアウト。自動リトライ・リダイレクト追従なし。3xxの応答もそのまま確認できる。
- ブラウザーのCookieは使わず、Rust側から送信する。Cookie保存・認証専用画面・キャンセル操作は未実装。

HTTPクライアントには[reqwest](https://docs.rs/reqwest/0.12.28/reqwest/struct.ClientBuilder.html)を使用する。
