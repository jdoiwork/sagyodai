# 試作の到達点と次段階への引き継ぎ

整理日: 2026-11-24

ユーザーの判断により、操作感と基本機能を検討する今回の試作はここで一区切りとする。これは[要件書の初期目標](requirements-and-design.md#5-最初に作る範囲)をすべて達成したという意味ではない。その時点では外部スクリプト・MCPは未実装だった。その後、次段階としてMCPを選び、基本操作を追加した（[MCP操作](mcp.md)）。外部スクリプトは未実装。

## 継続する設計方針

- Rustを正式なプロジェクト状態の所有者とし、TypeScriptの画面から共通操作APIで変更する。検証・Undo・保存を画面だけに実装しない。
- 入力原本と成功キャッシュを区別する。失敗時に前回の成功結果を消さず、更新待ち・エラーを利用者に示す。
- 表示上の検索・絞り込み・並べ替えと、後続へ渡す加工結果を明確に区別する。
- シートは表示の区分であり、別シートの計算や参照を止めない。閲覧位置はタブごと、プロジェクトの操作とUndoは共有する。
- 非表示シートでも未適用の下書きを保持する。ただし下書きとUndo履歴は、アプリ終了・再起動後の復元対象ではない。
- 当面は本人向けの開発版として、旧プロジェクト形式との互換性や移行基盤を求めない。現行形式の保存・復元と保存失敗時の保護は維持する。

Rust、TypeScript、React、React Flow、Vite、axumは現在の試作で使用している。Tauri、Glide Data Grid、Polars、SQLiteの採用は未確定。rmcpは、その後のMCP基本操作で導入した。試作の手応えを、候補技術の採用決定と扱わない。

## 操作感・性能から得たこと

ノード数が増えると、表示中のシートのノードが少なくてもスクロールが重くなる問題が報告された。パン・ズームの購読が画面全体に再描画を伝播し、毎回全ノードの入力情報を作り直していた処理を修正した。

- ビューポートの購読を小さなズーム操作バーへ分離した。
- 非表示シートのノードはマウントを維持しつつ、レイアウト・描画対象から外した。
- 「全体表示」は表示中のノードの既知の寸法だけで計算し、非表示ノードのDOM計測を待たないようにした。
- 改善後、ユーザーから操作感がよくなったとの反応を得た。FPSの定量比較や性能目標の達成を示す測定ではない。

今後も、下書きを保持することと、非表示部分に描画コストをかけないことを両立させる。DOMのメモリ使用量、プロジェクト更新時の全体処理、スナップショット転送・保存のコストは、必要になった段階で計測する。直ちに別の描画ライブラリへ置き換える判断はしていない。

## 残る制約・未検証事項

- セルは文字列。数値処理は個々の加工で解釈する方式で、型付き列・null・エラー値を統一的に扱うモデルは未実装。列単位の型、入力原文の保持、型エラー時の成功キャッシュ維持、安定した列IDを導入する方針は[要件書第2.10節](requirements-and-design.md#210-列の型と入力原文2026-11-24合意未実装)で合意済み。
- ノード・シートはIDを持つが、表の行列は位置に依存する。参照中の列の削除や並べ替えには制約がある。安定した行・列IDとスキーマ変更時の参照規則は次段階の検討対象。
- 外部スクリプト、DB入力、加工結果のCSV出力、Tauri組み込みは未実装。MCPは基本操作を追加済みで、全ノードの設定・外部通信・スクリプト実行は未対応。
- 上限は試作の保護用で、最大20シート・合計100ノード・表5000行／50列。手入力セルは100000バイト、外部入力・加工後キャッシュは1セル11 MiB、HTTPレスポンスは10 MiB、プロジェクト全体は128 MiB。各入力機能には別の制限もあるため、詳細文書を参照する。上限までの全組み合わせで快適性を保証するものではない。
- 未確定入力の障害復旧、世代別バックアップ、Undo履歴の永続化は未実装。
- macOSの実IME候補選択・再変換、実機のピンチ操作、Numbers／Excelからの直接貼り付け、Tauri WebView・Windowsは追加の手動検証が必要。日本語文字入力や模擬compositionイベントの検証とは区別する。
- ビルドには依存ライブラリ由来のディレクティブ警告と大きなチャンクの警告が残る。

## 次段階で決めること（試作終了時の候補）

この一覧のうちMCPを先に進めることを選び、最小ツール群とstdio接続を実装した。その後、列の型と安定した列IDの導入方針に合意した。型の実装は未着手で、詳細仕様とその他の順序は未決定。

1. 今の文字列表モデルを基礎に継続するか、型と安定した行・列IDを先に整えるか。
2. 外部スクリプトの最小仕様。別環境・別プロセス実行の方針は維持し、JSON Linesのスキーマ、空結果、ログ、キャンセル、出力上限を具体化する。
3. MCPの最小ツール群と接続方式。共通操作APIを利用し、人間との競合・実行権限・外部副作用をどう示すかを決める。
4. macOSへの提供形態と保存方式。現在のローカルサーバーを継続するか、Tauri等を検証するかを選ぶ。
5. 代表データと許容応答時間を決め、描画・更新・保存の性能を測る。

MCP以外の一覧は作業開始や優先順位の確定を意味しない。次の範囲を選ぶ際も、既存の操作感・保存・同期を回帰確認しながら進める。
