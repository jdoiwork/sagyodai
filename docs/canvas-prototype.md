# キャンバスと表編集の試作

2026-11-24、ユーザーの判断で今回の試作を一区切りとした。[到達点と次段階への引き継ぎ](prototype-review.md)を参照。以下は現在の操作説明と、それぞれの変更時の検証記録。

## 目的と構成

日本語入力、表計算ソフトからの貼り付け、拡大縮小した状態での編集、表とキャンバスの操作の競合を確認するための試作。製品の初期目標すべてを実装した段階ではない。

- 画面: React / TypeScript、React Flow、Vite。
- 表: HTML の table と textarea。IME を標準入力欄で扱う方式から検証し、Glide Data Grid の採否は保留する。
- 中核: Rust。表の更新、配置、Undo / Redo を共通操作で処理する。
- 接続: 試作用の axum HTTP アダプタ。Vite からローカルの Rust コアへプロキシする。
- 状態: Rust が確定操作をローカルへ自動保存し、起動時に復元する。[プロジェクトファイル](project-files.md) の手動書き出し・読み込みも可能。

Tauri の WebView への組み込みは未実施。ブラウザでの確認結果が、そのまま macOS WebView の IME 挙動を保証するわけではない。

## 起動とコードの配置

[ルート README](../README.md) の手順で起動する。

| 場所 | 担当 |
| --- | --- |
| `src/app/` | 全体画面、プロジェクトの表示状態、操作キュー |
| `src/features/canvas/` | 表ノードの表示・サイズ変更 |
| `src/features/table/` | セル入力、範囲選択、行の部分描画、TSV 変換 |
| `src/api/` | Rust への要求と応答の検証 |
| `backend/src/domain.rs` | 試作の表と操作の型 |
| `backend/src/application.rs` | 操作の確定、再計算の呼び出し、Undo / Redo、保存・復元の入口 |
| `backend/src/application/commands.rs` | 編集操作の検証・振り分け（確定前の表コピーに適用） |
| `backend/src/application/node_creation.rs` | ノードID・配置と種別ごとの初期値 |
| `backend/src/table_edit.rs` | 行列の編集、貼り付け、編集前の原本照合 |
| `backend/src/main.rs` | ローカル HTTP アダプタ |
| `scripts/dev.mjs` | 開発用プロセスの起動・停止 |

これは Tauri 採用時の配置例とは異なる試作用構成。中核に UI ライブラリへの依存は持たせていない。

画面の処理を読むときは、全体の組み立てを `src/app/App.tsx`、接続線の表示・接続操作を `useCanvasConnections.ts`、接続線のメニュー操作を `CanvasEdgeMenu.tsx` から追う。
表は `TableGrid.tsx` が表示を組み立て、`useGridViewport.ts` が部分描画・編集中セルの保持・セル移動、`useTableClipboard.ts` がコピーと貼り付け、`TableGridMenu.tsx` が行列メニューからの共通操作への変換を担当する。各ファイルは `src/features/canvas/` または `src/features/table/` に置く。

Rustでは `Project::apply` が編集用コピーの作成、操作、検証、再計算、履歴への記録、確定を順に行う。`application/` の子モジュールはこの境界の内側に置き、GUIとMCPの操作経路を共有する。

## 操作

| 操作 | 方法 |
| --- | --- |
| セル編集 | セルをクリックして入力。フォーカスを離すと Rust 側へ反映 |
| セル移動 | Tab / Shift＋Tab で左右、Enter / Shift＋Enter で上下 |
| 変換確定 | IME 変換中の Enter はセル移動に使わない |
| セル内改行 | Option＋Enter |
| 入力取消 | Escape でそのセルの編集前の値に戻す |
| 複数セル貼り付け | 起点のセルを選び、TSV を貼り付ける。足りない行列は自動追加 |
| 範囲選択 | 最初のセルをクリックし、最後のセルを Shift＋クリック |
| 範囲コピー | 範囲選択後に ⌘C。単一セルは入力欄の文字選択を使う |
| タイトル変更 | タイトル横の鉛筆ボタン、またはタイトルをダブルクリック。Enter／フォーカス移動で確定、Escape で取消。日本語 IME の変換確定 Enter は編集終了に使わない |
| 表の削除 | 表内の赤系の「削除」ボタン。接続も外れる。Undo で内容と接続を復元。最後の1ノードは削除不可 |
| 表の移動 | 表の見出しをドラッグ。画面端での自動パンは行わず、一度に一つの表を移動 |
| 表のサイズ変更 | 表を選択し、枠の端や角をドラッグ |
| 表内スクロール | 表の内側でスクロール。キャンバスのパンとは分離 |
| キャンバス移動 | 余白をドラッグ、または余白でスクロール |
| ズーム | ピンチ、右下の＋／−。倍率をクリックすると 100% に戻る |
| Undo / Redo | 左上の操作ボタン。最大30件の変更前状態を保持 |

入力欄での ⌘Z はブラウザのテキスト編集として扱い、プロジェクト全体の Undo はボタンで行う。

## 制限

- セルはすべて文字列。列名変更・行列の挿入／削除・複数選択／並べ替えは実装済み。列の型指定は未実装。
- 上限は試作の保護用として 1 表5000行・50列、合計100ノード、手入力1セル100000バイト、外部入力・加工後キャッシュ1セル11 MiB、HTTP 要求16 MiB・レスポンス10 MiB。製品としての容量目標ではない。
- 画面に近い行だけを描画する。編集中の行は画面外でも保持し、スクロールで変換中の文字を失わないようにする。
- 表 ID は安定しているが、行列は位置指定。製品版の行・列 ID は未実装。
- GUI の要求はタブ内で順番に実行し、SSE で別タブへ変更を通知する。詳細は [別タブ間の同期](tab-sync.md) を参照。
- 操作失敗時は入力内容を保持して再適用・破棄を選ぶ。セルの比較条件で同じセルへの意図しない上書きを防ぐ。
- ページを閉じる際に未書き出しの変更・未確定入力への警告を要求する。警告を無視して閉じると未確定入力は失われる。
- [フィルタフロー](filter-flow.md) と接続・設定・キャッシュの保存を追加済み。[外部スクリプト](external-scripts.md)の文字列表加工は試作後に追加した。MCPの基本操作は試作後に追加した（[MCP操作](mcp.md)）。

## 検証記録

2026-11-22、macOS 上のローカル試作で確認。

### 自動検査

- TypeScript 型検査と Vite ビルド。
- Vitest: TSV の日本語・空セル・改行・引用符、変換中の Enter 抑止、入力途中の保護、編集行の部分描画からの保護、貼り付け起点。
- Rust: 貼り付けによる行列拡張と一操作での Undo / Redo、不正な入力・古い revision の拒否。
- rustfmt / Prettier、Clippy。

ビルドには依存ライブラリ由来の `use no memo` と、500 KB 超のチャンクに関する警告が残る。型検査・ビルドは成功している。

### ブラウザで確認済み

- 日本語を含む2行4列の貼り付けと、一操作での Undo / Redo。
- 70%・150% 表示での日本語文字入力と Tab 移動。
- 見出しによる表の移動、枠からのサイズ変更と Rust 側への反映。
- 二つ目の表への1000行4列の貼り付け、表内スクロール。
- 表内スクロールでキャンバスの位置が変わらないこと。
- Shift＋クリックで選択した2行2列を TSV としてコピーできること。

### 表の移動に関する修正

表を動かすと別の表が遠くへ移動して見える問題への対策として、ノードのドラッグ時の自動パンを無効にした。キャンバス自体は余白のドラッグで移動する。

配置の同期はノードごとに管理し、ドラッグ・サイズ変更中、またはコアへの反映待ちの配置を、古い全体スナップショットで巻き戻さないようにした。複数ノードの同時選択移動は無効とし、表内の Shift＋クリックによるセル範囲選択は維持する。

- 回帰テスト: 表1の応答到着時に表2の反映待ち配置を保持、操作中の配置・測定情報を保持、確定後の Undo 配置を受け入れる。
- ブラウザ確認: 80% 表示で表1を画面上端まで移動しても表2の位置とキャンバスの変換が変わらないこと、および表2の移動時に表1が動かないこと。

### 人間による追加確認が必要

- macOS の日本語 IME の実際の変換候補ウィンドウ、再変換、確定・取消。自動テストは composition イベントを模擬し、ブラウザ操作では日本語文字の入力を確認したが、実 IME の候補選択は未確認。
- 使っているトラックパッドによるピンチの操作感。
- Numbers / Excel からの直接コピー＆ペースト。現時点は同形式の TSV をクリップボード経由で確認。
- Tauri の macOS WebView と Windows での動作。

まず「とうきょう」などを変換し、Enter で確定しても同じセルに留まること、もう一度 Enter で次の行へ移ることを確認する。その後70%・150%表示でも同じ操作を試す。

タイトル変更は入力・フィルタ・結果表で共通。接続は ID で維持し、保存・Undo / Redo・別タブ同期に反映する。空欄と1024バイト超は拒否し、同じタイトルの競合時は未反映の操作として入力を保持する。

## 行削除・列編集

- 手入力表の行（行番号またはセル）を右クリックし、コンテキストメニューの「行N を削除」で削除する。メニューは外側のクリック・Escape・スクロールで閉じる。最後の1行は残す。
- 列名をダブルクリックすると編集欄に切り替わる。キーボードでは列名にフォーカスして Enter / F2 でも編集できる。Enter またはフォーカス移動で確定、Escape で取り消す。日本語入力はセルと同じ変換中の確定防止を使う。列の追加は既存の「＋列」、削除は列見出しを右クリックして「「列名」列を削除」を選ぶ。最後の1列は残す。
- 削除メニューの項目にマウスを重ねると、対象の行または列（列見出しを含む）を赤系で強調する。マウスを外すかメニューを閉じると解除する。最後の1行・1列など削除できない項目は強調しない。
- 各操作は共通 API を通し、Undo / Redo・保存・別タブ同期の対象。削除時は表示時の表内容を照合し、途中に別の編集があった場合は拒否する。表示を確認して削除し直す。
- フィルタが参照中の列は削除できない。対象列の変更または切断後に削除する。他の列を削除した場合は、後続フィルタの列番号を補正する。
- 接続先に手動更新・更新待ち・エラーのノードがある場合、旧キャッシュの列構成を誤って解釈しないよう列削除を止める。自動更新に切り替えて更新待ち・エラーを解消するか、接続を外してから削除する。
- 結果表のセル値は引き続き読み取り専用。手入力表の行・列の複数選択削除は実装済み。列の型変更は未実装。結果表では[出力列の設定](output-columns.md)で列名・列順・出力対象を変更できる。

行・列の単一削除が反映されたとき、残った行・列を約220msで新しい位置へ移動させる。画面に描画中の部分だけを動かし、ズーム中も同じ座標単位を使う。削除失敗・Undoによる追加・他の編集が混ざる更新では削除アニメーションを行わない。OS の動きを減らす設定では無効にする。

## 列幅の変更

手入力表・結果表とも、列見出しの右端を左右にドラッグして列幅を変更できる。ドラッグ中にプレビューし、離すと1回の操作として確定する。境界にフォーカスして左右矢印キーでも10ずつ変更できる。ズーム倍率を考慮し、幅は60〜1200、未設定時は160。表全体に収まらない部分は横スクロールする。

列幅はノードごとの表示設定として保存し、別タブ同期・Undo / Redo に対応する。結果表のデータは読み取り専用のまま。列削除で残りの幅を詰め、新しい列には標準幅を使う。幅変更前の列構成と幅を照合し、競合時は上書きせず再操作を求める。

セル編集中は、その行番号と列見出しを緑系で強調する。フォーカス移動に追従し、セルからフォーカスが外れると解除する。削除対象の赤い強調表示を優先する。

## 列の並べ替え

手入力表の列見出し（列名・A/B などの記号・余白）を左右にドラッグし、移動先の列見出しに表示される挿入線へドロップする。左半分はその列の前、右半分は後への挿入。画面端では表を横スクロールする。ダブルクリックの列名編集、右端の幅変更とは別の操作。通常のカーソルは矢印のままにする。

列名・全行の値・列幅をまとめて移動する。後続フィルタの参照先と結果表の列幅も補正する。保存・同期・Undo / Redo に対応し、同時編集があれば拒否する。結果表の列順は、出力列の設定がない場合は入力に従う。接続先に手動更新・更新待ち・エラーがある場合は、自動更新へ切り替えて問題を解消するか、接続を外してから並べ替える。

表上のホイール操作は、表のスクロールで消費しきれない移動量をキャンバスへ引き継ぐ。上下左右を独立に判定し、Shift＋ホイールの横移動にも対応する。スクロール不要な小さな表では最初からキャンバスが動く。トラックパッドのピンチ操作はキャンバスのズームへ渡す。

手入力の表では、行・列ヘッダーをクリックして選択する。Shift＋クリックは範囲選択、⌘／Ctrl＋クリックは個別の追加・解除。選択したヘッダーを右クリックすると、選択した行／列を一括削除できる。セルの選択または Escape でヘッダー選択を解除する。表のデータや列構成が変わった場合も、添字の取り違えを防ぐため選択を解除する。削除は1回の Undo で戻せる。全行・全列の削除や、接続先が参照中の列の削除は拒否し、一部だけ削除された状態を残さない。

複数列の選択中に、選択した列のヘッダーをドラッグするとまとめて並べ替える。離れた列も元の左右順を保って、挿入マーカーの位置に連続して配置する。未選択の列をドラッグした場合はその1列だけを移動する。列幅とフィルタの列参照も追従し、Undo 1回で元に戻せる。移動後も移動した列の選択を新しい位置に引き継ぎ、続けてドラッグできる。移動失敗時は元の選択を維持する。

行も行ヘッダーのドラッグで並べ替えられる。複数選択した行は元の上下順を保ってまとめて移動し、未選択行をドラッグした場合はその1行だけを移動する。行の上下に挿入位置を表示し、表の上下端ではスクロールする。仮想化でドラッグ元が消えないよう移動中の行を保持する。移動後の選択維持、Undo 1回での復元、別タブの変更検出は列と同じ。自動更新の接続先には新しい行順を反映し、手動更新のキャッシュは通常の更新規則に従う。

行・列の右クリックメニューから、行の上／下、列の左／右に空欄を挿入できる。複数選択時は選択した数だけ、選択範囲の先頭より前／末尾より後にまとめて挿入する（離れた選択も同じ）。未選択の位置を右クリックした場合はその位置を基準に1行／1列を挿入する。一括挿入はUndo 1回で戻せる。新しい列名は既存名と重複しない「列 N」、幅は160。既存の列幅と接続先フィルタの参照は追従する。列構成の変更中に旧キャッシュを参照しないよう、接続先に手動更新・更新待ち・エラーがある場合の列挿入は拒否する。上限は既存と同じ5000行・50列。

挿入成功後は、新しく挿入した行・列をまとめて選択する。Rust の成功応答と画面のデータが一致した時点で選択を切り替え、失敗時は元の選択を保つ。応答待ちの間にユーザーが別の選択をした場合は、その選択を優先する。

列名が空欄・空白のみ・1024 UTF-8バイト超過の場合は、列名エディタ内で理由を表示し、入力を保持して修正できるようにする。無効な列名は送信しない。既存の未反映操作に無効な列名がある場合は再適用を無効にし、破棄して入力し直す案内を表示する。

ノードタイトルも、前後の空白を除いて空欄または1024 UTF-8バイト超過なら編集欄でエラーを表示し、無効な入力は送信しない。修正または Escape で取り消せる。既存の未反映操作に無効なタイトルがある場合は再適用を無効にして、破棄・再入力を案内する。

入力時の追加検証:

- 数値フィルタの比較値は有限の10進数（指数表記可）に限り、不正な値は条件欄で表示して適用を無効にする。文字列条件では空欄を許可する。比較値の上限は100000 UTF-8バイト。
- セルの上限は100000 UTF-8バイト。不正な下書きは送信せず保持し、表内のエラーとセルの無効表示で知らせる。修正または Escape で解消する。
- 範囲貼り付けは、開始位置を含めた5000行・50列と各セルのバイト数を送信前に検証する。
- 循環する接続候補は選択不可とし、接続線のドラッグでも拒否する。行・列・ノードの追加は上限に達したら無効にして理由をツールチップで示す。
- 既存の未反映操作のうち、貼り付け内容やフィルタ比較値そのものが不正なものは再適用を無効にして修正を案内する。通信失敗・別タブの変更との競合は、引き続き入力を保持して扱う。

位置・サイズ・列幅は既存のドラッグ制約、ファイル読み込みは既存のファイル検証で扱う。接続先の手動更新・参照列などに依存する構成変更の拒否は状態依存のエラーとして維持し、無条件に再適用しない。

実画面での入力検証（2026-11-22）:

独立した検証用コアとブラウザーで、空タイトル・空列名・長すぎるセル・51列の貼り付け・数値比較への文字入力を確認した。各エラーの表示と、正常な値への修正後の適用を確認済み。フィルタは数値 > 5 で2件、貼り付けは2列に縮小して成功し、最後にエラー表示と未反映操作がないことを確認した。タイトルのエラー色が既存スタイルに上書きされていた問題を修正し、タイトル・セル・比較値の無効な入力には赤い枠を追加した。日本語IMEの候補選択や上限操作すべての実画面検証は、この確認には含まない。

タイトルのエラーで入力欄が上へ詰まらないよう、ノードヘッダーは固定高ではなく最小高と上下12pxの余白を持ち、内容に応じて下方向へ広がる。実画面でエラー前後とも入力欄の上余白が12pxで変わらないことを確認した。

手入力の表の「＋100行」ボタンは「空行を削除」に置き換えた。全セルが空文字の行をまとめて削除する。空白文字・0・その他の値を含む行は残し、全行が空の場合は先頭の1行を残す。削除できる空行がないときは無効。既存の比較条件付き一括行削除を利用し、他タブの変更を保護してUndo 1回で復元できる。

ノード上部の左に「入力」、右に「出力」のラベル付き端子を表示する。出力から入力へドラッグして接続でき、入力端子から逆向きにドラッグする操作もReact Flowで扱う。手入力の表は出力のみ、結果表は入力・出力の両方を持つ。端子を22pxに広げ、接続判定の半径を28pxにした。既存の接続線の入力元側（出力端子のすぐ先）をドラッグして入力元をつなぎ替えられる。出力の分岐・入力元の置き換えは共通の接続操作を使い、循環接続を拒否する。プルダウンでの接続・未接続への変更も引き続き利用できる。

実画面で、手入力表→フィルタのドラッグ接続、接続線の端から別の手入力表へのつなぎ替え、フィルタ→結果表の接続と結果の更新を確認した。

接続線を右クリックすると「接続を解除」メニューを開く。選択すると接続先の入力元を未接続にし、共通のUndoで復元できる。Escape・外側クリック・キャンバス移動でメニューを閉じる。メニュー表示後にプロジェクトが更新された場合は古い線の操作を表示しない。

### 接続線・端子の色

線または入力／出力端子を右クリックすると、7色のパレットから個別に色を選べる。「標準色に戻す」で初期色に戻す。線のメニューには従来の「接続を解除」も表示する。端子からドラッグして接続すると、開始した端子の色を新しい線へ引き継ぐ（入力端子から逆向きに開始した場合は入力端子の色）。ドラッグ中の仮の線も同色で表示する。接続後に端子の色を変えても、既存の線の色は変更しない。線の色は接続先ノードに保持し、接続先の入力元を変更しても維持する。更新待ちの線は破線にして、指定色でも状態を区別する。

色は共通操作を通して変更し、プロジェクト保存・復元、別タブ同期、Undo／Redoの対象とする。

検証：独立した試作画面で線を赤、入力端子を紫、出力端子を青に変更し、選択色のチェック表示を確認した。自動テストで色の保存・復元、Undo／Redo、標準色への復帰、不正な対象の拒否、表データが変わらないことを確認した。

フィルターノード上のホイール操作は、見出し・設定欄・ボタン・余白を含めてキャンバス全体のスクロールに使用する。コンパクト表示でも同様。

### 手入力の表・結果表のコンパクト表示

見出しの「縮小」でフィルタと同じ380×102のコンパクト表示に切り替える。手入力の表は行数・列数、結果表は列数・件数・更新状態を表示する。表本体と編集操作は隠し、「展開」で元のサイズへ戻す。縮小中も移動・接続でき、表示状態は自動保存・別タブ同期・Undo／Redoの対象になる。

実画面で両種類のノードが縮小され、展開時に元の760×390へ戻ることと表データの保持を確認した。自動テストでは、縮小中に移動しても展開サイズを保持すること、保存・Undo／Redoで表示状態が復元されることを確認した。

### 集計フッター（SUM・最頻値）

手入力の表・結果表の下部にある「＋ フッター行」で追加する。列ごとに「集計なし／SUM／最頻値」を選び、「フッターを削除」で外せる。フッターはスクロール領域の下端に固定し、列幅・横スクロールに合わせて表示する。コンパクト表示では表本体と一緒に隠す。

SUMはRust側で表示中の全データ行を対象に計算する。空欄・数値以外・非有限値は無視し、数値がない場合は0。小数・負数・指数表記を扱い、桁区切りカンマ付き文字列は数値として扱わない。浮動小数点演算のため小数の丸め誤差はあり得る。合計が有限値の範囲を超えた場合は「集計範囲超過」と表示する。

最頻値は文字列の完全一致で数え、空欄・空白だけのセルを除外する。大小文字・前後の空白・数値の表記差は区別する。同率では元の行順で最初の値を表示し、対象がなければ「—」を表示する。SUM・最頻値ともクイック検索・列の表示絞り込み・表示並べ替えには影響されない。

フッターはデータ行ではなく、件数・フィルタ・接続先の入力には含めない。結果表は現在のキャッシュを集計し、更新待ち・エラー時も前回のデータと整合した集計を表示する。集計設定はノードごとに保持し、接続先へ自動伝播しない。列の挿入・削除・移動に追従し、保存・復元・同期・Undo／Redoに対応する。

検証：実画面でフッター追加とSUM選択、セル確定後に合計が17から34へ変化すること、結果表の合計も34となること、サーバー再起動後の設定・合計の復元を確認。自動テストでフィルタ後の集計、列操作への追従、手動キャッシュ、保存・Undo／Redo、空欄・非数値・合計の範囲超過を確認した。

## 表のクイック検索

手入力の表と結果表の上部で、全列の文字列を対象に部分一致でインクリメンタル検索できる。英字の大文字・小文字は区別せず、検索語の前後の空白は除く。表示件数／全件数を表示し、クリアボタンで全行表示に戻せる。

検索はノードごとの表示設定で、元データ、接続先への出力、SUMフッターの集計値には影響しない。SUMは全行を対象とする。検索語はプロジェクトに保存し、ページ・サーバー再起動後にも復元する。別タブ同期・Undoの対象とし、シート切り替え・コンパクト化でも保持する。

絞り込み後も元の行番号を表示し、セル編集・行削除は元の行に作用する。範囲コピーには表示行だけを含める。行の並べ替えと複数行の貼り付けは、非表示行への誤操作を防ぐため検索解除後に行う。列編集・単一行への貼り付けは引き続き利用できる。

検索と元行の対応、非表示行を含めないコピー、0件表示、集計値の維持、仮想スクロールの行対応を自動テストで確認。実画面でも検索・0件・コンパクト化後の保持と、検索前後で元データ・出力が変化しないことを確認した。日本語IMEの候補選択自体は手動確認が必要。

## 列の値による表示絞り込み

列ヘッダーのフィルターアイコンから、表示する値をチェックボックスで複数選べる。分類だけでなく、手入力の表・結果表の各列で使える。選択は即時に反映される。同じ列の選択値はOR、複数列とクイック検索はANDで組み合わせる。

一覧の件数はその列の全データに対する件数。「すべて表示」でその列の制限を解除し、「選択を解除」で全項目を未選択にできる。空文字も「（空欄）」として選択可能。検索欄の横の「列の絞り込みを解除」で全列の条件を解除する。

元データ・ノードの出力・SUMは変更しない。条件はプロジェクトに保存する表示状態であり、自動保存・手動書き出し・復元・別タブ同期・Undoの対象。シート切り替え・コンパクト化では保持する。列名・並びなど列構成が異なる状態には条件を適用しない。行の並べ替え・複数行貼り付けは、クイック検索と同様に絞り込み解除後に利用する。

自動テストで複数選択、検索との併用、解除、空欄、列構成変更時の保護、出力を変更しないことを確認。実画面では1000行の検証用コピーで2分類を選び500行表示になること、元データ・出力が変わらないことを確認した。


## 列による表示順の並べ替え

列ヘッダーのフィルターアイコンから「昇順」「降順」を選ぶと、その列で表示順だけを変更する。一度に1列を指定でき、対象列には矢印が表示される。同じメニューの「並べ替え解除」で元の行順に戻る。値の絞り込み・クイック検索と併用でき、並べ替えの解除は絞り込み条件を変更しない。

空欄以外がすべて数値の列は数値順、それ以外は日本語の文字列順（商品2は商品10より前）で比較する。同じ値は元の行順を維持し、空欄は昇順・降順とも末尾に置く。行番号は元データの番号のまま表示し、セル編集も元の行に作用する。範囲選択・コピーは表示順に従う。

元データの行順・出力・SUMには影響しない。設定はプロジェクトに保存し、ページ・サーバー再起動後にも復元する。別タブ同期・Undoの対象とし、シート切り替え・コンパクト化でも保持する。異なる列構成には適用しない。行のドラッグ移動・複数行の貼り付けは、表示の並べ替えと絞り込みを解除してから行う。

自動テストで数値・文字列・同値・空欄の順序、解除、表示順での選択とコピー、編集対象の元行への対応を確認。実画面でも昇順・降順・解除と分類絞り込みとの併用を確認し、操作元データ・出力が変わらないことを確認した。

表示設定の永続化は、実画面で検索語・2分類の選択・降順を設定し、検証用サーバーを停止・起動して56/1000行の表示が復元されることを確認。Undoと別タブ同期、および全ノードの元データ・出力が不変であることも確認した。日本語IMEの実候補選択は今回未検証。
