# プロジェクトファイルの保存と読み込み

## 使い方

画面右上の「保存」で `project.sagyodai.json` をダウンロードする。「開く」で保存済みファイルを選ぶと、確認後に現在の表を置き換える。読み込みは一操作として Undo / Redo できる。

保存ボタンは、セルからフォーカスが外れた際の確定操作を含め、送信済みの操作がコアへ反映されるのを待ってからファイルを生成する。

このボタンは自動保存とは別の手動書き出し。 ブラウザのダウンロード先を確認すること。アプリ側では「ダウンロード開始」までを扱い、利用者が保存ダイアログを完了したか、ディスクへの書き込みが成功したかは検知できない。同じファイルへの直接上書き保存は実装していない。

「未書き出しの変更あり」は、このタブで最後に読み込み・書き出しをした後の変更を表す。再読み込み後は保守的に未書き出し扱いにする。未書き出しの変更や未確定のセル入力がある場合は、ページを閉じる際にブラウザの確認を要求する。警告の表示自体はブラウザの挙動に依存する。

## サーバーの自動保存と起動時復元

確定した共通操作（表編集・配置・接続・設定・色変更・ファイル読み込み・Undo／Redo等）ごとに保存する。保存成功後に操作を確定し、応答と別タブ通知を返す。保存失敗時はメモリとUndo履歴も更新せず、画面の「未反映の操作」から再適用できる。

標準の保存先はリポジトリ内の `.sagyodai/project-<コアのポート>.json`。Gitには含めない。起動ディレクトリに依存せず、別ポートの検証環境とは分離する。`SAGYODAI_AUTOSAVE_PATH` で別のファイルを指定できる。同じ保存先を複数サーバーで同時使用しないようOSのファイルロックを保持する。

同じディレクトリの一時ファイルへ書き込み、同期してからrenameで置換する。書きかけの一時ファイルは起動時の復元に使わない。自動保存ファイルが不正・未対応形式の場合は、上書きせずエラーで起動を中止する。ファイルがない初回だけサンプルデータ（または指定した起動ファイル）を使用する。保存先を削除すると復元できなくなるため、長期保管には手動書き出しも利用できる。

自動保存は表・設定・キャッシュとrevisionを保持する。Undo／Redo履歴、未確定のセル入力、未適用のフィルタ下書き、パン・ズーム等の一時的UI状態は復元しない。「未書き出しの変更あり」は手動書き出しの状態であり、自動保存の失敗を意味しない。

## 現在保存するもの

- 表の ID と名前。
- 列名、文字列としての全セルの内容。
- 各ノードの位置とサイズ、種類、入力接続。
- フィルタ条件、自動／手動の選択、成功時の出力キャッシュ、更新待ち・エラー状態。
- ファイル形式の識別子とバージョン番号。

キャンバスのパン・ズーム、セルの選択、表内のスクロール位置、Undo 履歴は保存しない。未適用の条件の下書きや、スクリプトなど未実装の機能のデータも含まない。これは製品全体の保存要件の一部を実装した段階。

## 形式と検証

この段階では内容を確認しやすい JSON を使う。SQLite の採用判断は保留のまま。

| 項目 | 値・内容 |
| --- | --- |
| 拡張子 | `.sagyodai.json` |
| `format` | `sagyodai` |
| `formatVersion` | `2` |
| `tables` | 入力・フィルタ・結果表ノードの配列 |
| 容量 | 整形済み JSON で最大8 MiB |

Rust の `storage` モジュールが形式・バージョン・表数・ID の重複・行列の整合性・セルサイズ・配置を検証する。すべての検証が通るまで既存状態は変更しない。不正な JSON、非対応形式、容量超過の場合はエラーを表示する。旧形式（バージョン1を含む）の自動移行は行わない。接続先の存在・種類と循環も検証する。加工後の0件は正常な結果として保存できる。

ファイル生成はメモリ上で完了させてからブラウザへ渡す。アプリは既存のファイルを直接書き換えず、生成失敗時も既存ファイルとプロジェクトを維持する。ディスクへの最終書き込みはブラウザに委ねる。

## 実装

- `backend/src/autosave.rs`: 自動保存・ロック・復元・保存成功後の状態確定。
- `backend/src/storage.rs`: ファイルの生成・検証。
- `backend/src/application.rs`: 既存プロジェクトへの反映と Undo。
- `src/features/project/ProjectFiles.tsx`: 保存・ファイル選択・確認・通知。
- `src/app/ProjectContext.tsx`: 操作キュー、書き出し待ち、未書き出し状態。

`GET /api/project/export` はファイルと書き出し時点の revision ヘッダを返す。読み込みは共通操作 API の `openProject` を使い、通常の操作と同じ revision 検査を行う。ファイルの内容はローカルコアへ送信するだけで、外部サービスへ送信しない。

## 開発用の独立環境

通常の作業とテストを競合させないため、別ポートでも起動できる。

```sh
SAGYODAI_CORE_PORT=4319 SAGYODAI_WEB_PORT=5174 npm run dev
```

既存ファイルをコア起動時に読み込む場合は `SAGYODAI_STARTUP_PROJECT` にファイルのパスを指定できる。ファイルが不正なら起動を中止する。自動保存ファイルが既に存在する場合はそちらを優先し、この設定は使わない。この設定は開発用で、通常の利用では画面の「開く」を使う。

複数タブで開くと同じプロジェクトを共有するため、ファイル読み込みも他タブへ反映される。未反映の操作がある場合は解消してから保存する。詳細は [別タブ間の同期](tab-sync.md) を参照。

自動保存の検証（2026-11-22）:

- 独立したHTTPサーバーで日本語・改行を含むセル、フィルタ接続、キャッシュ、色を変更し、SIGKILL後の再起動で全ノードとrevisionが一致することを確認。
- 書き込みを意図的に失敗させ、HTTPエラー、メモリ・保存ファイル・履歴の維持、障害解消後の再適用を確認。
- Undoした結果が次の再起動でも保持されることを確認。
- 不正な自動保存ファイルで起動が中止され、ファイルが上書きされないことを確認。
- Rustテストで保存先の同時使用拒否とロック解放も確認。実機の電源断とWindowsでは未検証。
