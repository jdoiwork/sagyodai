# プロジェクトファイルの保存と読み込み

## 使い方

画面右上の「保存」で `project.sagyodai.json` をダウンロードする。「開く」で保存済みファイルを選ぶと、確認後に現在の表を置き換える。読み込みは一操作として Undo / Redo できる。

保存ボタンは、セルからフォーカスが外れた際の確定操作を含め、送信済みの操作がコアへ反映されるのを待ってからファイルを生成する。

**自動保存ではない。** ブラウザのダウンロード先を確認すること。アプリ側では「ダウンロード開始」までを扱い、利用者が保存ダイアログを完了したか、ディスクへの書き込みが成功したかは検知できない。同じファイルへの直接上書き保存は実装していない。

「未書き出しの変更あり」は、このタブで最後に読み込み・書き出しをした後の変更を表す。再読み込み後は保守的に未書き出し扱いにする。未書き出しの変更や未確定のセル入力がある場合は、ページを閉じる際にブラウザの確認を要求する。警告の表示自体はブラウザの挙動に依存する。

## 現在保存するもの

- 表の ID と名前。
- 列名、文字列としての全セルの内容。
- 各表の位置とサイズ。
- ファイル形式の識別子とバージョン番号。

キャンバスのパン・ズーム、セルの選択、表内のスクロール位置、Undo 履歴は保存しない。接続・加工・出力キャッシュ・スクリプトなど、未実装の機能のデータもまだ含まない。これは製品全体の保存要件の一部を実装した段階。

## 形式と検証

この段階では内容を確認しやすい JSON を使う。SQLite の採用判断は保留のまま。

| 項目 | 値・内容 |
| --- | --- |
| 拡張子 | `.sagyodai.json` |
| `format` | `sagyodai` |
| `formatVersion` | `1` |
| `tables` | 表の配列 |
| 容量 | 整形済み JSON で最大8 MiB |

Rust の `storage` モジュールが形式・バージョン・表数・ID の重複・行列の整合性・セルサイズ・配置を検証する。すべての検証が通るまで既存状態は変更しない。不正な JSON、非対応形式、容量超過の場合はエラーを表示する。旧形式の自動移行は行わない。

ファイル生成はメモリ上で完了させてからブラウザへ渡す。アプリは既存のファイルを直接書き換えず、生成失敗時も既存ファイルとプロジェクトを維持する。ディスクへの最終書き込みはブラウザに委ねる。

## 実装

- `backend/src/storage.rs`: ファイルの生成・検証。
- `backend/src/application.rs`: 既存プロジェクトへの反映と Undo。
- `src/features/project/ProjectFiles.tsx`: 保存・ファイル選択・確認・通知。
- `src/app/ProjectContext.tsx`: 操作キュー、書き出し待ち、未書き出し状態。

`GET /api/project/export` はファイルと書き出し時点の revision ヘッダを返す。読み込みは共通操作 API の `openProject` を使い、通常の操作と同じ revision 検査を行う。ファイルの内容はローカルコアへ送信するだけで、外部サービスへ送信しない。

## 開発用の独立環境

通常の作業とテストを競合させないため、別ポートでも起動できる。

```sh
SAGYODAI_CORE_PORT=4319 SAGYODAI_WEB_PORT=5174 npm run dev
```

既存ファイルをコア起動時に読み込む場合は `SAGYODAI_STARTUP_PROJECT` にファイルのパスを指定できる。ファイルが不正なら起動を中止する。この設定は開発用で、通常の利用では画面の「開く」を使う。
